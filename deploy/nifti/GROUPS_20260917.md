# NIfTI 分割组第一版

界面将一个来源 mask 文件的多个标签组织为一个逻辑 SegmentationSet，组内每项为一个 Segment（分割目标）。
底层仍使用独立二值 labelmap，因此组内、组间都能叠加，编辑和历史仍以原 maskId 为单位。
这一版只改 NIfTI 分割栏和分组持久化；完整 Case/Report/Finding manifest 尚未实现。

## 用户操作

- 导入一个多标签 NIfTI：一个组，多个目标。重复导入同名本地文件不会自动合并。
- 组头展开/折叠、整体显示、整体透明度；目标各自显示、锁定、定位、改名、改色和查看历史。
- 选择目标会将它设为当前画笔/AI 目标，并显示该目标；展开组和查看历史不切换编辑目标。
- 顶部“新建二值 mask”加入当前编辑组；“组内新增”明确加入该组；“新组与目标”创建新组。
- 保存、历史恢复不新建组；历史“另存为独立标注”在同组创建新目标。
- “复制为新方案”在先保存组内目标后，复制当前已加载成员到一个新组，记录每个目标的来源版本。
  必须另点 Save All 才保存新方案；复制取消、失败或内存不足时移除此次部分副本，保留原目标。
- 移除目标只从当前视图移除，服务器历史仍在；未保存的修改会明确提示。
- 可见性、锁定和透明度是当前浏览状态；分组身份、名称、来源及成员关系会持久化。
- 暂无整组一键恢复和分组改名/移动；历史仍然属于每个分割目标。

## 存储与兼容

新增 SQLite `segmentation_groups(source,id,metadata)` 和 `segmentation_group_members(source,mask_id,group_id)`。
每个原图内，一个目标只属于一个组。API 的 mask 元数据增加可选 `segmentationSet`；
新保存的 sidecar 和导出 ZIP 清单携带该字段。已有文件、maskId 和版本不重写。

旧数据优先按 `manifest_imports` 记录的实际导入批次恢复分组；独立副本通过 derivedFrom 继承来源组。
不使用 basename、尺寸或名称相似性推断同源；缺少可验证来源时保留单独组。
历史查询返回当前逻辑归属，历史像素、保存时名称等仍取原始版本。
重复迁移幂等；组身份绑定 source，已有目标不能通过 save 请求被移动到另一个组。

组名中的 finding_0 仅是来源名称的缩写，尚不代表建立了报告语义关联。
ReX 原始样本为两个 finding 文件、六个目标（标签分别 1/2/3 和 1/2/4）。
正式病例另有一份没有来源/副本关联的旧 Mask 7；迁移后独立保留为第三组，不自动归入任一 finding。

## 验收

- pytest：多标签同组、同名不同导入隔离、保存/恢复/副本归属、旧批次迁移幂等、历史文件哈希不变、非法字段拒绝。
- Jest：本地多标签分组、默认加入当前组、已保存目标和历史副本保留组、原有加载失败恢复和内存预算。
- groups-acceptance.cjs：Stack 分组、目标选择、整体/个体显隐、MPR 透明度继承、直接打开目标历史、组内新增、Save All、复制方案、刷新重载、病例关闭释放。
- annotation-history-acceptance.cjs：旧响应保护、只读预览、同身份恢复、独立副本和来源跳转。

已完成：pytest 133 项、Jest 11 项通过；隔离环境的组内新增→保存→复制方案→保存→重新打开闭环通过。
历史恢复、CSV/颜色保存重载/MPR 回归通过。十轮病例开关后源数据、影像缓存、内存 ledger 和颜色表计数归零；
128 MiB 体载入后滚动 50 次无网络请求，本机 headless Edge p95 为 4.6 ms。
本轮未修改 DICOM 功能代码，未重新运行真实 GPU AI 或 DICOM interpolate 全流程验收。
正式 9443 验证通过：ReX 的两个来源组和单独的旧 Mask 7 共三组、七个目标；所有原 maskId、名称、
版本号及版本数与发布前一致，直接从目标行进入正确历史。浏览器无报错，无标注 POST 请求。
正式首页、鉴权（匿名 401）、原图库 5 例、DICOM 列表 4 例及数据目录配置验证通过。
