# NIfTI 第一阶段可用性修复

范围：入口可读性、设置菜单、导入选项说明、保存状态和独立目标颜色。
病例树、报告侧栏、Finding–Channel 数据模型及目录同步留待后续阶段。

## 用户可见变化

- 列表正文 16px、辅助文字 14px、标题 24px；主要导入按钮至少 40px 高。
  使用显式尺寸，避免项目主题的 text-sm=12px / text-base=13px 再次造成误差。
- 设置齿轮包含“导入默认设置”“数据来源与保存说明”。菜单通过 Portal 提升层级，
  对话框可滚动、适应较小窗口，并支持 Escape 关闭。
- CT/MR 与缺失单位设置移入导入对话框。默认值可在本机浏览器保存，
  清单导入时固定本次类型；后来修改默认值不会更改该清单。
  类型仅登记元数据，不更改体素、不自动应用窗宽窗位、不会把 CT 自动视为 HU。
- “服务器原图库”改为“已保存病例”；“已入库”改为“原图已保存”。
  首页说明应用存储与文件夹同步的区别，工作台单独显示标注保存状态。
- “清单基准目录”改为导入对话框里的“相对路径起点”，说明只对相对路径生效。
  绝对路径清单在列表中明确标记无需路径起点。
- 文件名收起到可展开的“X 个分割文件”。未解析前明确说明目标数量在加载后确认，
  不将文件数量冒充 Finding 或 Channel 数量。
- 独立目标分配不同初始色。颜色作为可选 displayColor 随 NIfTI mask 版本保存，
  改色可触发未保存提示；保留旧版本无颜色字段的加载兼容性。
- 原生目标使用独立且跨视图共享的色表，Stack 与 MPR 不再重新创建默认红色。
  调色通知所有相关视图，删除目标或关闭模式时释放所拥有的色表。

## 验证与发布

- 后端原生与 DICOM v1 稳定性测试：125 passed；包括颜色版本化、旧字段兼容、
  无效颜色不提交记录、仅改色不改变 mask 像素。
- Node 颜色测试：2 passed；首轮 12 个独立目标无重复初始色，输入/顺序相同结果可复现。
- 浏览器 phase1-acceptance：菜单命中、默认值持久化、清单类型隔离、实际字体大小、
  分割文件展开、颜色保存重载、三平面颜色一致、1100×700 / DPR 2 对话框检查。
- DICOM 实际 Interpolate 按钮回归：两个种子层 800 体素补为 11 层 4400 体素，
  使用同源 WASM/JS。
- 当前通过的浏览器与内存记录归档到 release-artifacts/nifti-phase1-20260916；
  以 phase1.json、memory.json 和 production-ui.json 的 passed 字段为准。
