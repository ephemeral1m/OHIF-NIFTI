# 原生 NIfTI 使用说明

当前功能用于单用户调试和研究。现有 DICOM 工作台仍使用原入口；原生
NIfTI 使用 `/nifti` 入口，界面和画笔沿用现有 OHIF/Cornerstone 工作台。

## 打开原图

1. 在 DICOM 检查列表选择带立体文件图标的“NIfTI”，或访问 `/nifti`。
   专属主页提供服务器原图库、清单病例、搜索和分页。
2. 点击“打开本地原图”，在对话框中选择 CT、MR 或“未指定 · 通用强度”，再选择文件。
   类型仅用于登记原图信息；窗宽窗位预设在看图工具栏中选择。选择 CT 不会把体素转换为 HU。
   文件未声明空间单位时，可在高级选项中明确选择单位。
3. 本地打开只在浏览器解析。可以滚动、调窗、缩放、平移、测量，并通过
   布局工具切换三平面 MPR。刷新本地页面需要重新选择文件。
4. “已保存病例”可打开应用已经保存的原图；这里不扫描或同步服务器目录。
   已上传原图的访问链接支持刷新恢复，
   并沿用 `/monai` 入口的鉴权；链接本身不包含密码。

支持 NIfTI-1 三维 uint8、int8、uint16、int16、float32。原始体素与缩放后
体素分别不超过 512 MiB。4D、NIfTI-2、颜色/矢量/复数、无可信空间矩阵及
shear 网格会被拒绝。米、毫米、微米统一换算成毫米 LPS 进行显示和测量。

## CT-RATE 和服务器 CSV / JSON 清单

在 NIfTI 检查列表点击“导入 CSV / JSON”，在对话框中确认导入类型及路径选项。
vanilla 已配置只读根目录 `/data/cache/datasets/CT-RATE`；清单中的相对路径以所选“相对路径起点”为起点，
也可使用该根目录内的绝对路径。服务器目录不会被修改。
ReX 示例衍生标注目录也已单独以只读方式开放。绝对路径清单无需调整路径起点。
右上角设置菜单提供导入默认设置和数据来源说明；默认设置只影响之后导入的新原图，
不会改变已经导入的清单或覆盖已保存病例的类型。

CSV 第一列为原图，第二、第三列是可选 segmentation；可省略表头或使用：

```csv
image,segmentation1,segmentation2
dataset/valid_fixed/valid_668/valid_668_b/valid_668_b_2.nii.gz,,
```

JSON 支持对象数组或按同样列顺序排列的数组：

```json
[
  {
    "image": "dataset/valid_fixed/valid_668/valid_668_b/valid_668_b_2.nii.gz",
    "segmentations": [],
    "name": "CT-RATE valid_668"
  }
]
```

需要分割时，在第二、第三列或 `segmentations` 数组加入真实 `.nii` / `.nii.gz`
路径（最多两个文件）。示例见 `deploy/nifti/examples/ct-rate.csv` 和 `ct-rate.json`。
清单先显示可打开和无效病例及原因；点击病例的打开图标时才登记原图并导入分割。
多标签文件自动拆为独立组。重复打开同一文件清单不会重复创建已导入组。
原图有效但某个分割不匹配时仍可看图，面板会显示该分割失败原因。

只允许读取已配置根目录内的文件，包含符号链接的路径同样检查最终位置。
如需增加数据目录，管理员需同时添加后端只读挂载及 `NIFTI_IMPORT_ROOTS`，
不能只在清单中填写任意服务器路径。

## 编辑、导入与保存

- “新建二值 mask”创建一个独立分割组和一个 Segment，并选为当前目标。
  在 NIfTI 面板点击目标名称切换当前 mask；使用“画笔”“橡皮”和不透明度
  滑块编辑与查看。每组提供显隐、颜色、重命名和删除操作。删除仅移除当前
  浏览器中的组，不删除已保存的服务器版本。
- “导入 mask”允许选择多个文件。多标签文件的每个非零整数值都会成为
  独立组；例如 300、900 不会被截断成 uint8 标签。不同组允许重叠。
- 导入会检查完整物理网格。只有无需插值的轴置换/翻转可以自动对齐；
  需要重采样或配准时会明确拒绝。概率图不能自动当作标签图。
- “上传原图”将原文件保存到服务器。原文件保持不变，名称、来源及空间
  信息保存在独立索引中。同一原图的压缩/非压缩形式可以识别为同一 source。
- “Save All”会先上传尚未登记的原图，再分别保存各 mask。失败项仍为
  未保存状态，可以在服务恢复后重试；不会丢弃当前浏览器中的编辑。
- 独立目标使用不同初始颜色；颜色随 mask 版本保存，Stack、MPR 和刷新重载保持一致。
  改颜色也会显示未保存状态。“原图已保存”与“标注已保存”分别表示原图和标注的状态。
- “标注历史”（时钟图标）打开独立标注的版本轨迹。顶部按颜色和名称选择标注；
  超过四份时可搜索名称、下拉选择。选择标注不会改变工作台的当前编辑目标。
  下方只显示这份标注的历史，可加载更早版本；重命名仍属于同一条轨迹。
- “只读预览”在独立区域显示历史 mask 叠加原图，可拖动切片滑块；不创建可编辑分割，
  不替换当前像素。结束预览、切换标注或关闭窗口会释放预览缓冲。
- “恢复为新版本”需要确认，在同一份标注中追加一版并记录来自哪个历史版本。
  保留当前标注名称、旧版本和其他标注。该目标有未保存修改时禁止恢复，需先保存；
  发生保存冲突时先导出 ZIP 备份，再移除当前目标并加载服务器最新版。
- “另存为独立标注”才会创建副本，分配独立颜色。Save All 后它拥有独立轨迹，
  可通过来源链接回看原标注的具体版本。
- “加载这份标注的最新版本”仅更新选中且没有未保存修改的目标。
  “补充加载其他标注”加载尚未打开的标注，已加载目标保持原编辑状态。
  这里尚不是整例病例快照；工作区全生命周期另行接入。
- “导出 NIfTI ZIP（本地）”无需上传。ZIP 内每个组有独立 `.nii.gz`，并附
  来源和标签清单。导出恢复原图网格，不合并重叠目标。
- 纯 NIfTI 的 PACS 保存不可用。DICOM 原图的既有草稿、DICOM-SEG/PACS
  流程继续使用原工作台。

## nnInteractive

先创建或选择一个 mask。NIfTI 复用 DICOM 的 Interactive Segmentation 工具栏：
通过 Points、Box、Scribble 图标及原有正负提示设置进行操作；悬停图标可看工具提示。
如果原图尚在本地，这一步会先上传原图，成功后才启用提示工具。上传失败
时原图和 mask 保留在浏览器。运行结果只写入当前选中的组。

Live Mode 沿用现有设置；关闭时使用“运行 nnInteractive”提交提示。
“重置 AI 会话”清理当前提示会话，并保留已有 mask；下一次提示会携带完整
seed 重新同步。切换目标、服务重启或旧请求迟到时，身份、版本及 token 校验
阻止结果写入错误目标。

## 画笔和 Interpolate

Segmentation Tools 沿用 DICOM 工具栏，包括画笔大小、形状、橡皮和插值。
点击分割组标题会将该组选为当前编辑目标。Interpolate 需要在同一目标的至少
两个不同切片上画出轮廓，然后点击插值图标；它填充中间切片，不能从单层推断完整目标。
插值运行时等待完成；失败会显示通知。所需 WASM/JS 已随站点部署，无需访问外部 CDN。

## 资源与故障恢复

默认浏览器工作集预算为 1.5 GiB，可用 `niftiWorkingSetBytes` 配置。源数据、
mask、导入/导出及 AI 请求的临时缓冲都需要预算；空间不足时先关闭原图或
删除不再需要的 mask。关闭时会清理 NIfTI 私有缓存和相关 Cornerstone 资源。

上传、解析中可以取消。服务忙碌会返回 429；稍后重试即可。遇到版本冲突，
先保留本地 ZIP，再重新加载服务器版本。前后端 context v2 不匹配时必须
成套更新，不能退回未经验证的 DICOM 请求。

下载首屏与载入后的滚动是两项不同的性能。Tailscale 中继、VPN 或带宽问题
仍可能影响下载；原图完全载入后滚动不应再次请求切片网络数据。
